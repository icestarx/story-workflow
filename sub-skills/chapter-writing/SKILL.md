# 正文写作子Skill

## 触发方式
- `/chapter-writing`
- 「写第X章」
- 「创作第X章正文」

## 功能
根据细纲创作单章正文，输出统一格式的文件。集成/story-long-write的10步单章写作流程。

## 输入参数
```
chapter_number: 章节编号（如：1, 2, 3...）
project_path: 项目根目录路径
```

## 输出文件
```
{project_path}/正文/第{chapter_number:03d}章_{chapter_title}.md
```

## 执行步骤（12步，集成/story-long-write流程）

### 步骤1：检查细纲
**操作**：检查细纲是否存在，如果不存在必须先补建细纲再写正文
**输出**：确认细纲文件存在
**关键文件**：
- `{project_path}/大纲/细纲/第{chapter_number:03d}章_细纲.md` - 本章细纲
**规则**：不允许跳过细纲直接写作，补建时参考卷纲中本章对应的事件规划和上下文

### 步骤2：读取上下文（10个文件）
**操作**：读取以下文件获取章节上下文（可选快捷路径：如果项目已部署story-explorer agent，可spawn Agent一次获取上下文）
**输出**：完整的章节上下文
**关键文件**：
1. `{project_path}/正文/第{chapter_number-1:03d}章_*.md` - 上一章正文
2. `{project_path}/大纲/细纲/第{chapter_number:03d}章_细纲.md` - 本章细纲（含钩子设计）
3. `{project_path}/追踪/伏笔.md`（如存在）- 待回收伏笔
4. `{project_path}/设定/角色/{相关角色}.md` - 本章涉及角色
5. `{project_path}/对标/{对标书名}/拆文报告.md`（按对标书路径查找）- 对标参考
6. `{project_path}/对标/{对标书名}/原文/第{chapter_number}章_*.md`（如存在）- 同位置章节参考
7. `{project_path}/参考资料/{topic}.md`（如存在）- 历史研究资料（由story-researcher产出）
8. `{project_path}/追踪/角色状态.md`（如存在）- 角色当前状态快照
9. `{project_path}/对标/{对标书名}/剧情/故事线.md`（按对标书路径查找）- 剧情线索引
10. `{project_path}/对标/{对标书名}/剧情/{相关剧情线}.md`（按对标书路径查找）- 相关剧情线
**缺失文件回退**：所有文件是可选增强，缺失时按优先级降级，不报错不阻塞

### 步骤3：状态筛选（准备层3.1）
**操作**：从角色状态.md中筛选本章涉及角色的当前状态，从伏笔.md中筛选本章需要回收/推进的伏笔
**输出**：最简记忆包
**关键文件**：
- `{project_path}/追踪/角色状态.md` - 角色当前状态快照
- `{project_path}/追踪/伏笔.md` - 伏笔系统
**规则**：如果角色状态文件不存在，从角色设定和前文推断

### 步骤4：模块召回（准备层3.2）
**操作**：确定本章目标情绪词、借鉴哪个参考文件的哪个技法、用在哪些段落
**输出**：模块召回结果
**关键文件**：
- `{project_path}/参考资料/` - 写作技法参考
- `{project_path}/对标/` - 对标书结构化子目录（角色/剧情/设定）
**规则**：答不出 → 先回读参考再动笔

### 步骤5：指令确认（准备层3.3）
**操作**：综合细纲+最简记忆包+模块召回结果，确认本章节奏（快/慢）和情绪目标，用一句话概括本章写作意图
**输出**：写作意图确认
**示例**：「快节奏打脸——读者等了三章，这章必须一拳到位。技法=信息差揭示（hooks-suspense.md），用于第2-4段。」

### 步骤6：资料研究（按需）
**操作**：如果写作中遇到需要查证的外部事实（历史年代、地理方位、职业细节等），spawn story-researcher agent搜索并输出到参考资料/目录
**输出**：研究完成后再继续写作
**规则**：研究完成后再继续写作

### 步骤7：写作
**操作**：如果项目已部署narrative-writer agent，spawn Agent执行正文写作；如未部署，由主线程直接写作
**输出**：正文内容
**Agent调用**：
```
Agent(subagent_type: "narrative-writer", prompt: "项目目录：{dir}\n任务描述：写正文\n章节：第{N}章\n细纲文件：大纲/细纲_第{N:03d}章.md\n上一章：正文/第{N-1:03d}章_*.md\n准备层输出：{3.1最简记忆包 + 3.2模块召回结果 + 3.3写作意图}\n情绪目标：{从准备层3.3确认}\n涉及角色：{从准备层3.1筛选}\n参考技法：{从准备层3.2召回}\n⚠️字数硬约束：本章必须达到细纲中设定的字数目标（{从细纲读取}字）。使用wc -m统计字数，不要用wc -c。字数未达标禁止结束本章。")
```
**字数硬约束**：
- 默认最低字数：3000字/章
- 细纲另有标注时以细纲为准
- 低于最低字数的章节必须补足后再继续

### 步骤8：字数验证（写作完成后的第一件事）
**操作**：用`wc -m`（或`python3 -c "print(len(open('正文文件路径', encoding='utf-8').read()))"`）统计本章实际字数
**输出**：字数验证结果
**规则**：如果字数 < 细纲目标的 90%，**回到细纲补充更多子事件/情节点**，然后用场景展开法将这些新子事件写成正文，直到字数达标后再进入步骤9。禁止用堆砌感知层/反应层的方式凑字数。

### 步骤9：检查
**操作**：检查章尾是否有钩子、爽点是否到位
**输出**：检查结果
**检查项**：
- 情绪交付是否到位？
- 爽点是否突出？
- 钩子是否有效？
- 字数是否达标？

### 步骤10：禁用词扫描
**操作**：对照`references/banned-words.md`检查本章，一级词（高频AI腔）命中即替换；二级词（低频/语境相关）高频出现时替换，偶发可参考`references/anti-ai-writing.md`定性裁定
**输出**：禁用词扫描结果
**关键文件**：
- `{project_path}/参考资料/banned-words.md` - 禁用词列表
- `{project_path}/参考资料/anti-ai-writing.md` - 去AI味参考

### 步骤11：更新追踪文件
**操作**：写完后即时更新追踪文件
**输出**：更新后的追踪文件
**关键文件**：
- `{project_path}/追踪/伏笔.md` - 更新伏笔状态（新增/回收伏笔）
- `{project_path}/追踪/时间线.md` - 记录事件时序
- `{project_path}/追踪/角色状态.md` - 更新角色状态（如本章引起角色状态变化——身份、能力、关系、公众形象——则更新对应角色条目并追加变更记录）
**规则**：角色状态更新规则详见state-tracking.md

### 步骤12：中途快照（长篇写作安全网）
**操作**：每连续写完3章，在继续前执行以下快照操作
**输出**：快照完成
**快照内容**：
1. 将当前进度写入`追踪/上下文.md`（只更新进度元信息——当前位置、最近决策、待处理线索——不重复角色状态/伏笔的具体内容）
2. 用`ls -la 正文/`确认最近3个章节文件已成功写入磁盘且大小正常（>100 bytes）
3. 如果发现文件缺失或大小异常，立即重新写入
**规则**：快照完成后可继续写作
**注意**：日更模式下此步骤自动跳过——workflow-daily Step 2已按章更新上下文.md

## 正文文件模板

```markdown
# 第{chapter_number}章 {chapter_title}

{chapter_content}

---

## 章节信息
- **章节编号**：第{chapter_number}章
- **所属卷号**：第{volume_number}卷
- **实际字数**：{actual_word_count}字
- **目标字数**：{target_word_count}字
- **完成时间**：{completion_time}

## 伏笔操作记录
- **埋下伏笔**：{foreshadow_planted}
- **回收伏笔**：{foreshadow_resolved}
- **推进伏笔**：{foreshadow_advanced}

## 角色状态变化
| 角色 | 状态变化 | 关系变化 |
|------|----------|----------|
| {character_name} | {status_change} | {relationship_change} |

## 情绪曲线
- **开篇情绪**：{opening_emotion}
- **高潮情绪**：{climax_emotion}
- **结尾情绪**：{ending_emotion}

## 写作说明
- {writing_note_1}
- {writing_note_2}
```

## 调用方式

主workflow调用此子skill时：
```
调用story-long-write技能，使用chapter-writing子skill
参数：chapter_number={N}, project_path={path}
```

## 并行支持
- 多章正文写作可以并行执行，但需要考虑上下文依赖
- 建议并行批次：2-3章/批（避免上下文冲突）
- 或者串行执行，每章完成后更新追踪文件

## 全局一致性检查
- 每章正文完成后，检查是否符合全局框架
- 检查伏笔操作是否与伏笔系统一致
- 检查情绪设计是否与情绪弧线总图一致
- 检查角色状态是否与角色关系图谱一致
- 检查事实一致性（时间、地点、人物关系）
