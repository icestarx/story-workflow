# 最终质量检查（步骤 136–145）

对锁定正文执行全书级审计。不要把“去 AI 味”当成不可验证的判断；报告必须展示重复结构、套话、同声对话或解释堆积的可定位证据。

## 覆盖步骤

136. 创建最终检查目录；137. 并行审读章节情绪交付；138. 并行检查技术质量；139. 扫描用户/平台配置的禁用项；140. 诊断机械化表达；141. 更新追踪文件；142. 创建全书质量报告；143. 创建全书总结报告；144. 展示文件清单；145. 等待项目完成确认。

## 执行

运行：

    python scripts/audit_manuscript.py --project-dir path/to/project --expected-chapters N
    python scripts/build_story_docs.py --project-dir path/to/project --force

### 十至二十章交付质量门

每完成 10–20 章，或在继续下一章前发现质量疑点时，除技术扫描外必须独立核对三类可定位证据：

1. **预算兑现**：逐章比较正文非空白字符数与细纲“字数预算”。默认低于下限 70% 或高于上限 130% 为偏差，连续两章偏差必须进行人工交付复核；只有证实场景、情绪、因果或承诺被压缩时才记 S2。作者可批准短章，但例外、理由和补偿章节必须留档；不得以补设定、解释或文书注水作为修复。
2. **时间状态**：逐项对读相邻正文的日期、时辰、相对时长、地点、伤势/资源、倒计时，与 `正典/时间线.md` 和细纲的入章/交付状态比对。时间倒流、漏记跨日，或会污染下一章人物状态、物证期限、知识边界的差异记 S1：立即暂停下一章/批次，交 `canon-management` 做最小修正并回归。审计不得直接改写锁定正文。
3. **体验重复**：标注本周期每章的主冲突类型、阶段回报和核心能力/代价是否实际改变选择。连续三章以同一种程序、追逐或对话结构解决，或核心能力连续十章只作为设定存在时，记 S2；下一批细纲须提供不同机制的场景，不能以“仍待验证”反复替代行动后果。

由多个独立审读任务分别检查情绪兑现与叙事体验；自动脚本检查缺章、标题、用户词表命中、重复段落和高频句首。将技术审计、上述质量门和人工结论合并至 `审校/最终/质量报告.md`；所有文件/目录名遵循项目文件契约的中文命名。禁用项、S1、未解决 S2、作者批准的例外与开放项必须进入总结报告。

禁用词表只使用 项目/禁用词.txt 中作者/平台明确要求；结果是命中清单而非自动删改。
