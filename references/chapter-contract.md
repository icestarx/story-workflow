# 章节细纲与正文契约

## 细纲的必填结构

每一章使用 细纲/第一章.md 的形式。以下标题必须全部存在，内容可以是“无 / TBD”，但不能静默缺失：

    # 第 N 章：标题
    ## 章节信息
    ## 入章状态
    ## 核心事件与因果
    ## 场景节拍
    ## 情绪曲线
    ## 章首钩子
    ## 爽点与代价
    ## 伏笔操作
    ## 角色状态变化
    ## 章尾钩子
    ## 字数预算
    ## Canon 冲突检查

字段要求：

| 字段 | 最低内容 |
|---|---|
| 章节信息 | 卷 / 章节号、章节功能、承接与交付；自动生产时还要写状态：锁定、Canon 版本：x.y.z |
| 入章状态 | 人物、地点、时间、资源、伤势、关系、已知信息 |
| 核心事件与因果 | 触发—行动—阻力—结果—新局面 |
| 场景节拍 | 4–8 个有行动或信息变化的节拍 |
| 情绪曲线 | 目标情绪、起止强度、至少一次变化 |
| 章首钩子 | 立即可感知的异常、冲突、问题或期限 |
| 爽点与代价 | 获得什么、凭什么获得、支付或埋下什么代价 |
| 伏笔操作 | 新设 / 推进 / 回收 / 无；有责任章节或窗口 |
| 角色状态变化 | 谁在目标、关系、资源、伤势、知识或立场上发生变化 |
| 章尾钩子 | 具体未决问题或更高压力；标明下一章要接住什么 |
| 字数预算 | 目标总字数、场景预算或上下浮动范围 |
| Canon 冲突检查 | 已检查的 Canon ID、结果、冲突和处理方式 |

## 锁定与重基

计划细纲覆盖全书；写正文前把目标章重基到最新 Canon，形成“锁定细纲”。若最新事实使细纲无效，先改细纲，再写正文。锁定后若改动影响本章因果、信息边界或章尾承诺，必须重新审校。

受 batch_controller 管理时，在“章节信息”中明确写 `状态：锁定` 与 `Canon 版本：<当前版本>`。控制器拒绝没有这两项、字段不完整或版本不匹配的细纲；下一章在前一章 Canon 提交后必须重新重基。

## 正文边界

正文以场景行动、感知、选择和后果承载信息。不得为了说明设定而暂停因果；不得让角色越过知识边界；不得把承诺的爽点变为无成本巧合。章节结尾可以保留问题，但问题必须来自本章已发生的事实或可追溯的压力。
