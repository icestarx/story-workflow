# 并行、快照与合并规则

并行能提高候选方案和独立检查的速度，不能绕过叙事因果或 Canon 提交。所有并行任务必须有输入快照、明确输出位置、责任人和合并顺序。

## 可并行的任务

| 工作 | 前提 | 输出状态 |
|---|---|---|
| 多个立项方向 | 互不覆盖同一项目决策 | 候选 |
| 资料调研 | 问题边界已定义 | 研究笔记 |
| 世界冻结后的力量、势力、谜案候选 | 仅引用同一世界快照 | 候选 Canon |
| 不同、互不重叠角色的背景草案 | 不提交关系或秘密 | 候选 Canon |
| 同一快照中、不重叠的章节规划批次 | 只写候选细纲 | 候选细纲 |
| 已锁定章节的独立审校 | 不修改正文或 Canon | 审校报告 |

## 不可并行的任务

- 相邻或存在直接承接关系的正文起草；
- 对同一 Canon 文件、registry.json、状态、时间线、伏笔账本的直接写入；
- 尚未锁定的相邻章节的最终细纲；
- Canon 冲突、重大反转、角色知识变化、关系转折的最终决定；
- 同一章节的多份正文被当作可无损合并的片段。

## 合并协议

1. 记录快照：Canon 版本、输入文件版本、任务范围、允许修改的路径；
2. 隔离输出：候选保存在任务专用文件或段落，不覆盖已确认内容；
3. 串行审查：先校验事实，再检查相互依赖、章节承接和读者体验；
4. 决策：采用、拒绝、保留候选或要求重做，并记录理由；
5. 提交：只有 canon-management 更新 Canon；只有 chapter-outline 锁定细纲；
6. 失效处理：如果 Canon 版本已变，候选输出必须重基，不能直接合并。

## 批次规则

- 阶段 4 的第 1–30 章是校准批次，必须先复核首章和首卷承诺；
- 后续每批最多 100 章，批次结束检查章节功能重复、伏笔窗口、情绪与字数；
- 可并行的只是“规划候选”，不是连续剧情正文；
- 出现 S1 或 Canon 版本变化时暂停受影响批次，完成影响分析后恢复。
