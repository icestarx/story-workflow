# 项目参数控制指南（200万字支撑版）

## 核心原则
1. **参数化控制**：根据总字数自动调整所有参数
2. **动态章节数**：根据项目大小动态计算总章节数
3. **全局一致性**：所有参数都要符合全局框架

## 参数计算公式

### 1. 每章字数
```
words_per_chapter = 3000-5000字（根据题材调整）
- 仙侠题材：4000字/章
- 都市题材：3500字/章
- 悬疑题材：4000字/章
- 言情题材：3000字/章
```

### 2. 总章节数
```
total_chapters = total_words / words_per_chapter
- 200万字 ÷ 4000字/章 = 500章
- 150万字 ÷ 4000字/章 = 375章
- 100万字 ÷ 4000字/章 = 250章
```

### 3. 主要角色数
```
main_characters = 根据总字数调整
- 200万+：8-10个
- 150-200万：6-8个
- 100-150万：4-5个
- 50-100万：3-4个
- 50万以下：2-3个
```

### 4. 配角数
```
supporting_characters = main_characters × 2
- 200万字：8×2=16个
- 150万字：7×2=14个
- 100万字：5×2=10个
```

### 5. 反派数（分层设计）
```
反派分层设计：
- 幕后大boss：1个（贯穿全书）
- 中期反派：volumes × 0.5（每卷1-2个）
- 前期反派：volumes × 1（每卷1个单元谜案反派）
- 反派阵营：1-2个

200万字反派结构：
- 幕后大boss：1个
- 中期反派：8×0.5=4个
- 前期反派：8×1=8个
- 反派阵营：2个

150万字反派结构：
- 幕后大boss：1个
- 中期反派：6×0.5=3个
- 前期反派：6×1=6个
- 反派阵营：1-2个

100万字反派结构：
- 幕后大boss：1个
- 中期反派：4×0.5=2个
- 前期反派：4×1=4个
- 反派阵营：1个
```

### 6. 卷数
```
volumes = total_chapters / chapters_per_volume
- 200万字（500章）：500÷62=8卷
- 150万字（375章）：375÷62=6卷
- 100万字（250章）：250÷62=4卷
```

### 7. 每卷章数
```
chapters_per_volume = 50-80章（平均62章）
- 前期卷：50-60章
- 中期卷：60-70章
- 后期卷：70-80章
```

### 8. 单元谜案数
```
unit_mysteries = volumes × 1
- 每卷一个单元谜案
- 200万字：8卷=8个单元谜案
- 150万字：6卷=6个单元谜案
```

### 9. 伏笔数
```
foreshadows = total_chapters / 12
- 200万字（500章）：500÷12≈42个
- 150万字（375章）：375÷12≈31个
- 100万字（250章）：250÷12≈21个
```

### 10. 势力数
```
factions = main_characters × 1.25
- 200万字：8×1.25=10个
- 150万字：7×1.25=9个
- 100万字：5×1.25=6个
```

## 动态调整机制

### 1. 章节数调整
- 如果某卷内容过多，可以拆分为两卷
- 如果某章内容过长，可以拆分为两章
- 动态调整总章节数

### 2. 角色数调整
- 如果角色过多，可以合并一些配角
- 如果角色过少，可以增加一些配角
- 动态调整角色数

### 3. 伏笔数调整
- 如果伏笔过多，可以合并一些短期伏笔
- 如果伏笔过少，可以增加一些短期伏笔
- 动态调整伏笔数

### 4. 卷数调整
- 如果内容过多，可以增加卷数
- 如果内容过少，可以减少卷数
- 动态调整卷数

## 注意事项

1. **参数不是固定的**：根据实际写作情况动态调整
2. **全局一致性**：所有参数都要符合全局框架
3. **并行化执行**：识别可并行的步骤，提高执行效率
4. **子skill复用**：主workflow调用子skill，子skill处理单章逻辑
