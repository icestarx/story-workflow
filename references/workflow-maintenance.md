# 工作流的持续自审

小说项目与写作 Skill 都是长期系统。每次阶段完成、批次 halt、出现吃书、审校反复失败或用户指出流程问题时，做一次流程复盘。

1. 先记录现象、输入、预期、实际结果和影响，不把偶发创作分歧误判为系统缺陷；
2. 先运行 diagnose_project.py，检查路由、文件契约、Canon 提交权、上下文、批次状态机和质量门；
3. 对改设运行 trace_canon_impact.py；对修复运行 run_regression_suite.py，并用最小项目/fixture 复现确定性问题；
4. 将项目级问题写入 审校；只有用户请求改 Skill 时才修改 Skill 本身；
5. 修改后重新运行格式校验、脚本验证、批次状态机、阶段覆盖审计和 regression suite。

自审的成功标准不是步骤越多，而是每一个状态变化都可恢复、每一个暂停都可解释、每一项创作决策都有恰当的人类控制权。
